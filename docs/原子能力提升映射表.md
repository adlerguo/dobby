# 原子能力提升映射表

> 目标：从三份标准化服务内容中抽取通用原子能力，不聚焦政务场景，用于评估 `6qiyeagent` 后续可以集成的能力。
>
> 状态口径：
> - 已具备：项目中已有主体能力，可继续打磨。
> - 可增强：已有基础，适合继续做。
> - 待建设：当前缺少明确实现，需要新模块或较大改造。
> - 不建议近期做：投入大、偏重平台化，短期性价比低。

## 推荐优先级

| 优先级 | 选择原则 |
|---|---|
| P0 | 能补齐现有主链路短板，投入可控，做完可直接提升产品质感或验收能力 |
| P1 | 有明确价值，但需要一定产品设计或数据结构扩展 |
| P2 | 偏高级能力，适合作为版本规划或客户项目增强 |
| P3 | 重平台、重算法、重集成，短期不建议作为通用产品能力 |

## 暂不建议作为近期目标

| 原子能力 | 原因 |
|---|---|
| 知识图谱/本体建模 | 会把产品带向重知识工程平台，短期投入大 |
| 复杂实体关系抽取 | 没有图谱产品承接时价值不足 |
| 多模态切片和多模态预处理 | OCR/ASR/图像视频链路重，依赖多 |
| 多智能体复杂协同 | 容易增加不可控性，应先把单智能体流程和评测做好 |
| 长期记忆召回 | 企业隐私、权限、审计要求高，需谨慎设计 |
| RLHF 式知识进化 | 对数据量和训练链路要求高，先做人类反馈和测试集增强 |
