# 工具安全配置说明

> 面向管理员与实施。说明高风险工具的默认安全态与开启方式。

## 1. 默认安全态（开箱即安全）
平台对高风险工具采取"默认关闭、显式授权"：

| 能力 | 默认 | 风险 |
|---|---|---|
| 代码类工具执行 | 禁用（enable_auto_code_tools=false） | 任意代码执行 |
| HTTP 外部调用 | 无可访问主机（http_tool_allowed_hosts 为空） | SSRF / 数据外泄 |
| 外部 MCP 执行 | 即将支持（暂不执行） | 外部服务调用 |

未配置前，这些能力即使在工具中心可见，也不会被智能体真正执行。

## 2. 如何安全开启
仅在确有业务需要且评估风险后开启：

**代码类工具**
1. 将 `enable_auto_code_tools` 设为 true。
2. 在 `code_tool_allowlist` 中按工具名或 ID 显式列出允许的工具（白名单制，不配即全部禁止）。

**HTTP 工具**
1. 在 `http_tool_allowed_hosts` 中列出允许访问的主机（白名单）。
2. 只加内部可信服务地址，避免使用通配。

## 3. 建议
- 生产环境默认保持关闭；确需开启走审批。
- 白名单最小化，定期复查。
- 沙箱当前为本地可信环境最小加固版；不可信代码/多租户场景需替换强隔离方案（gVisor/nsjail/独立容器池）。
- 工具的启用、绑定操作已纳入审计，可在审计记录追溯。
