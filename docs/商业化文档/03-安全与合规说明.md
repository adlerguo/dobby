# 安全与合规说明

> 面向客户的安全与合规评估材料。本文档说明平台在数据、访问、加密、审计等方面的设计，供采购、信息安全和合规团队评估。

## 1. 总体安全立场

平台按"数据不出企业边界"设计，支持完全私有化部署。企业的模型密钥、知识库内容、对话数据、审计记录全部存储在企业自有环境内，平台不向外部回传业务数据。

## 2. 数据安全

### 2.1 数据不出域
- 支持私有化部署，全部数据与计算在企业内网/私有云内完成。
- 知识库文档、切片、向量、对话历史存储于企业自有数据库。
- 外部模型 API 调用可通过企业统一网关出口，或对接私有化模型实现完全内网闭环。

### 2.2 敏感凭证加密
- 接入的模型渠道密钥采用对称加密（Fernet/AES）存储，数据库中不保存明文。
- 加密主密钥在部署时生成并持久化；平台在检测到弱密钥或默认密钥时拒绝启动，避免"裸奔"上线。

### 2.3 多租户隔离
- 数据按租户强隔离，租户之间不可互相访问。
- 可进一步用工作空间在租户内按项目隔离资源。

## 3. 访问控制

### 3.1 身份与认证
- 用户密码采用加盐 PBKDF2-SHA256 存储，迭代次数达 21 万次，抵御离线暴力破解。
- 会话采用签名令牌（JWT）机制。

### 3.2 基于角色的权限（RBAC）
内置四级角色，按最小权限分配：

| 角色 | 权限范围 |
|---|---|
| 平台管理员 | 全部 |
| 租户管理员 | 用户/角色、知识库、发布、看板、审计 |
| 构建者 | 知识库、发布、运行数据 |
| 普通成员 | 查看与使用 |

权限细分到操作级（如"发布智能体""查看审计""授予角色"），可按企业组织结构裁剪。

### 3.3 对外调用的凭证与限额
- 发布出去的应用通过独立访问密钥调用，密钥可绑定作用域。
- 每个密钥可设速率与配额（每分钟速率 / 每日请求数 / 每日 Token / 每日成本），超限即拒，防止滥用与成本失控。

## 4. 审计与可追溯

- 关键操作全程审计：模型接入、智能体变更、发布、工具绑定、用户与角色管理等。
- 审计记录支持按用户、动作、资源、时间检索，并支持接口数据导出（现成 Excel/CSV 文件下载可在交付时按需接入），满足合规留痕要求。
- 每次对话可追溯完整运行轨迹（模型调用、知识库检索、工具调用），回答可回溯到来源片段引用，支持问题定位和责任界定。

## 5. 内容与回答可信

- 智能体回答基于企业知识库，并给出可查的来源引用（来源文档与命中片段），减少"编造"。
- 提示词可设置回答边界，制度未覆盖时按预设话术回复而非猜测。

## 6. 部署侧安全建议（交付时执行）

- 修改默认管理员密码，关闭演示模式。
- 为加密主密钥、令牌密钥配置强随机值并妥善托管。
- 生产环境启用 HTTPS，合理配置反向代理。
- 沙箱/工具执行环境：当前内置沙箱为本地可信环境的最小加固版；对于多租户 SaaS 或不可信代码执行场景，需替换为强隔离方案（gVisor、nsjail 或独立容器池）。

## 7. 合规适配说明

平台的数据本地化、加密、权限、审计能力可作为企业满足内部信息安全制度及行业合规要求的技术支撑。具体合规认证（如等保、行业标准）需结合企业部署环境与管理制度共同实现，平台提供技术层面的可配置能力。

---
*本说明基于平台当前版本能力。部署环境的安全性还取决于企业的网络、主机与运维管理措施。*
