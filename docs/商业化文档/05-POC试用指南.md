# POC / 试用指南

> 面向售前与客户，用 1–2 天在客户真实数据上跑出可感知效果。

## 目标

不是展示全部功能，而是**用客户自己的一份资料，跑通一个业务问答闭环**，让客户看到"我的知识变成了能用的助手"。

## 建议选题

优先选"制度问答"或"内部知识助手"——资料好准备、效果直观、当天可见。避免一上来就做需要接工具的复杂场景。

## 前置准备（客户配合）

- 一份代表性资料（如某类制度文件、产品手册），10–50 页即可。
- 一个可用的对话模型和向量模型的 API Key（或使用私有化模型）。
- 5–10 个真实业务问题，作为验收题目。

## 两天节奏

**第 1 天：搭建**
1. 部署/开通环境，管理员登录。
2. 接入对话模型、向量模型并测试连通。
3. 创建知识库，上传客户资料，等待解析完成。
4. 做命中测试，用真实问题确认能召回正确片段。

**第 2 天：调优与验收**
1. 创建智能体，写好提示词（身份/边界/输出/不确定处理）。
2. 用 5–10 个验收问题在调试对话中逐题验证。
3. 针对不满意的回答，迭代提示词或补充资料。
4. 发布为外部应用，演示一次接口调用（含流式）。
5. 打开观测中心，展示运行数据与可追溯的引用。

## 验收标准（与客户提前约定）

- 验收问题中 ≥ 80% 回答符合业务口径且带正确引用。
- 回答可追溯到原文出处。
- 可对外发布并成功调用。

## 常见坑与规避

- **资料太口语/太长** → 命中差。提前拆分、用正式术语版本。
- **提示词太空** → 回答发散。用四段结构写清边界。
- **拿演示模型验收** → 效果不真实。务必用真实模型。
- **问题与资料术语不一致** → 命中偏少。验收题贴近资料用词。

## 交付物

POC 结束给客户一份简短小结：验收题通过情况、典型问答截图、下一步规模化建议。可套用《客户案例模板》。
